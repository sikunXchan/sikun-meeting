# Sikun Meeting 自律AI組織化の要件

作業ID：20260924-autonomous-ai-organization  
状態・更新日：レビュー用下書き・2026-09-24  
根拠：2026-09-23〜24のユーザーとの会話、Sikun MeetingのREADMEと現行コード

## 目的と範囲

既存のSikun Meetingを、AIたちの会議を眺めるアプリから、AIたちが継続して活動し、実用的な成果物を作る仕組みへ発展させる。会社経営と、複数人格によるコミュニティ・文化形成は構想候補。最初にどちらを主軸にするかは未決定。Orca上で実装し、要件・設計・タスクを仕様レビュー画面に順番に提出する。

## 現行コードで確認した事実

| ID | 現状 |
|---|---|
| F-01 | Electron + TypeScript製。21種類の専門家ペルソナがあり、会議参加者を招集・一時除籍できる。 |
| F-02 | Claude Agent SDKの`query()`を参加者ごとに逐次呼び出す。各回にその会議の議事録全文を渡す。 |
| F-03 | 使用可能なツールは`Read`・`Grep`・`Glob`のみ。ファイル変更、コマンド実行、PC操作は現状できない。 |
| F-04 | 決定者は人間の`chief`に固定されている。Action Itemは記録・完了チェックできるが、AIによる自動実行はない。 |
| F-05 | 会議、発言、決定、Action ItemはローカルJSONに保存される。円陣UIで発言中の参加者を表示できる。 |
| F-06 | モデルを役割やタスクごとに選ぶ仕組み、継続実行のスケジューラ、利用量上限、長期記憶は見当たらない。 |

主な確認先：`README.md`、`src/core/types.ts`、`src/core/agent/claudeAgent.ts`、`src/core/agent/promptBuilder.ts`、`src/core/services/discussionService.ts`、`src/core/services/decisionService.ts`。

## 受け入れ条件の下書き

| ID | 前提・操作 | 期待する結果 | 検証方法 |
|---|---|---|---|
| AC-01 | 既存の会議を開く | 21種類のペルソナ、議事録、既存の決定・Action Itemが引き続き利用できる | 既存データを使った手動確認と型・ビルド検査 |
| AC-02 | 仕事を割り当ててAIを実行する | 担当者による実作業と成果物が保存され、観察画面から辿れる | 専用の試験作業を実行し、ログとファイルを照合 |
| AC-03 | EngineerがDesigner所管の方針変更を提案する | 提案と採用済みの方針が区別され、定めた確認過程を経るまで採用済みにならない | 役割境界のシナリオテスト |
| AC-04 | 実行を停止し、アプリを再起動する | 重複実行や状態消失なく、保存した位置から確認・再開できる | 中断・再起動テスト |
| AC-05 | 利用上限に達する、または呼び出しが失敗する | 新しい呼び出しが止まり、理由と未完了作業が表示される | 模擬エラー・上限テスト |
| AC-06 | Sonnet・Haikuを設定して実行する | 指定した割り当てと実際の使用モデルが記録で確認できる | 設定・実行ログの確認 |

## 未確定事項・設計上の衝突

1. **完全なPC全体操作権限と、役割外の行動の事前防止は両立しない。** 任意のシェル操作やGUI操作を全員が直接実行できるなら、アプリ内の担当規則やプロンプトだけでは、Engineerがデザインを書き換える行動自体を確実には止められない。求める水準が「事後検知して採用を止める」か「操作前に確実に遮断する」かを決める必要がある。後者には実効的な権限制約・隔離が必要で、U-02の意味を調整することになる。
2. **自律的な最終決定権。** 現状は人間の`chief`だけが決定する。AIだけでどの種類の決定まで進めるか、最終採用の責任者を誰にするかは未決定。
3. **PC全体操作の範囲。** ローカルファイル・GUI・ブラウザに加え、送信、公開、購入、削除、設定変更など外部または不可逆の操作を含めるか未決定。
4. **最初の実用成果物。** ソフトウェア、調査、コンテンツなど、AI組織に最初に何を作らせるか未決定。
5. **会社と文化形成の優先順位。** 最初の実装で会社活動だけを扱うか、関係・慣習の変化も扱うか未決定。
6. **継続運転の条件。** 常時稼働、定時起動、仕事やイベントがある時だけ起動のいずれか未決定。並列数、呼び出し上限、1日の予算も未決定。
7. **モデル利用の費用。** 使用するClaudeプラン・認証方式、APIキー利用の有無、許容する追加課金は未確認。
8. **レビューとOrca。** 要件承認後に設計、設計承認後にタスク、タスク承認後に実装する。OrcaにCodexが表示されない原因は未特定。対象フォルダは現状Gitリポジトリではない。

# Codex実行エンジンの要件

作業ID：20260924-codex-provider
状態・更新日：実装・検証済み・2026-09-24
依頼の根拠：ユーザーはSikun MeetingでCodexも利用し、その後CodexでGitHub上の `sikun-cyber-security` を改良して実用的な成果物を作りたい。対象URLは `https://github.com/sikunXchan/sikun-cyber-security` と指定された。
製品要求：`docs/product-requirements.md` の委託フロー（P-001〜P-006）。

## 現状と要求

実装前に確認した事実：委託案件の相談・計画・実作業・内部確認・納品はClaude Agent SDKの単一実行クライアントを通っていた。新規案件はClaudeモデルで作られ、既存案件の設定には実行エンジン種別がなかった。Codex CLI 0.156.1はこのPCでChatGPTログイン済みで、公式Codex SDK 0.156.1から読み取り専用の実呼び出しに成功した。対象リポジトリの正しいURLは当初未特定だった。

追加で確認した事実：ユーザー指定の `sikunXchan/sikun-cyber-security` を取得できた。生コマンドからHTTP(S) URLの接続先を抽出する処理は認証情報・ポート・IPv6を正しく扱えず、WindowsではGit BashがあってもWSL起動用の`bash.exe`が選ばれ、並行したHTTP検査が失敗した。

ユーザーの要求：新規委託案件でCodexを選べるようにする。続いてCodexを使い、`sikunXchan/sikun-cyber-security` に実用的な改善を加える。

今回の提案：既存Claude経路を保持し、案件単位で「Claude / Codex」を選択する。Codex案件はITコンサルタントとの相談から内部確認まで公式Codex SDKで動かし、納品文もSDKで生成を試みる。内部確認済みの成果があり、納品文の生成だけが失敗した場合は、検証済みの記録から機械的な納品文を作って成果を失わない。指定した作業ディレクトリの成果は既存の案件・Run・ファイル・レビュー履歴へ保存する。Codexの既定モデルは、この会話でユーザーが選択した `gpt-6-sol` とする。Codex SDKで観測できない実応答モデルや料金を推測して表示しない。

## 未確定事項と制約

- 対象リポジトリはユーザー指定の `https://github.com/sikunXchan/sikun-cyber-security` に確定。別リポジトリで代用しない。
- Codex SDKの実行イベントには、要求モデルの実応答モデルを確定するフィールドがない。UIでは要求モデルと「応答モデル未確認」を区別する。
- 初期版は委託案件でCodexを選ぶ。既存の円陣会議発言の実行エンジン変更は、この実用成果物の経路には必要ないため対象外とする。
- Codex SDKはChatGPTログインを利用できる一方、未ログインの配布先では本人のログインが必要。認証情報をアプリ独自に保存しない。
- Codexの相談・計画は読み取り専用、実作業・内部確認は既存の全権限方針に合わせる。SDKにClaudeと同じ最大ターン数指定がない場合は、時間制限と案件の呼び出し回数を維持し、UIで誤認させない。
- 初回のCodex縦断試験では相談・計画・ファイル作成・内部確認を通過したが、納品文のSDK呼び出しが5分の試験期限まで終わらなかった。この失敗を成功扱いせず、納品文の時間制限と確認済みデータからの代替報告を設計する。

# 会議統治と継続実行の要件

依頼の根拠：2026-09-25のユーザー提案（部門別権限、議決、外部MCP、成果物カルテ、停止条件、独立監査、初回独立意見、モデル割当）

## 着手時に確認した現状

- 会議とコミュニティの初回発言は招集順に保存され、後のAIに前の発言が渡る。独立した初回意見の段階はない。
- 会議のAIは全員同じ `allowedTools: Read/Grep/Glob` で呼ばれる。`tools` 自体の明示的な制限、部門別のMCP、スキル、モデル指定はない。
- 委託案件はフェーズ別とペルソナ別にモデルを指定できる。実行権限は読み取りとフル権限の二段階で、フル権限は部門ごとに分けられていない。
- `votingEnabled` と `maxAutoRoundsPerAsk` は会議タイプに記録されるが、議決や実行回数の判定に使われていない。会議の確定は人間による決定文入力で行われ、定足数・証拠・反対意見の扱いに機械的な条件はない。
- 外部MCP接続、成果物単位のカルテ、独立監査、KGIに基づく継続判定は未実装。委託案件には呼び出し回数・ターン数・時間・再試行回数の上限がある。

## 目指す動作

1. **初回意見の独立性**：最初の一巡では各AIが他のAIの未公開意見を見ずに回答する。全員の回答を確定してから開示し、次の討論を始める。失敗した回答は投票に数えず、再試行や欠席を記録する。
2. **議決条件**：決定案、根拠、必要な部門、参加者の有効な最終見解、少数意見、未解決リスク、担当と完了条件を記録する。議決条件を満たした「推奨」と、人間が確定した「決定」を別の状態にする。投票対象の会議には定足数と必要な専門領域を設定する。
3. **能力と権限**：ペルソナごとに役割、使用モデル、スキル、閲覧可能な情報源、利用可能なツール、外部アカウントの操作種別を明示する。権限は仕事・段階・対象リソースで絞り、実行時に検査する。肩書きやプロンプトだけに依存しない。
4. **外部実行**：メール、カレンダー、会計、チャット等のMCP接続は読み取り、下書き、送信・確定を分離する。外部副作用は操作前に対象、内容、権限、重複実行防止キーを記録し、実行結果を追跡する。取り消し不能または高影響の操作は人間が確認する。
5. **成果物カルテ**：アプリ・ツール単位で現状、KGIと測定値、既知の問題、改善バックログ、成果物、検証証拠、過去の決定、最終更新時刻を管理する。次の会議開始時に関連カルテの版を固定して読み、参照した版を議事録に残す。
6. **継続判定**：AI自身の「完了」宣言だけで終了しない。人間が確定した達成条件、測定可能な証拠、未完了項目、最低限の検証段階を照合する。トークン数は労力の目安とし、単独の達成条件にしない。上限、無進捗、障害、外部確認待ちには停止または一時停止を許す。
7. **独立監査**：通常部門とは別の監査設定と読み取り専用権限を使い、過去の決定、カルテ、実測KGI、議事録を照合する。監査結果から是正課題を作るが、監査AIは元の決定や証拠を書き換えない。周期と対象は設定可能にする。
8. **文脈の衛生**：人間の確定事項、検証済み事実、AIの提案、外部入力を区別する。カルテは根拠と版を持つ要約を使い、古い・矛盾する記憶の失効と訂正を記録する。外部コンテンツは命令として扱わない。

## 受け入れ条件（実装時）

| ID | 条件 | 検証 |
|---|---|---|
| AC-01 | 4人の初回回答が互いの回答を含まない同一の議題スナップショットから生成され、全員分がそろってから開示される | 模擬AIでプロンプトと保存順を検査 |
| AC-02 | 無発言、エラー、必要部門欠席、未解決の高リスクでは「議決可能」にならず理由が表示される | 状態遷移試験 |
| AC-03 | 部門と段階にないツール・MCP操作は実行前に拒否される | 権限表の単体試験 |
| AC-04 | 外部操作は実行前の記録、確認、実行結果、再試行時の重複防止を備える | 模擬MCP試験 |
| AC-05 | 新しい会議が関連カルテの固定版を読んだ証跡を残し、古い知識を無条件で最新事実として使わない | 保存・プロンプト試験 |
| AC-06 | 目標未達でAIが「完了」と言っても停止せず、無進捗や上限では理由付きで停止する | 模擬実行試験 |
| AC-07 | 監査は元の決定を変更できず、KGIと根拠を照合した監査記録だけを追加する | 権限・状態遷移試験 |
| AC-08 | ペルソナ別モデル指定が会議・コミュニティに適用され、要求モデルと実際に使ったモデルを区別して記録する | 模擬SDKと実SDKの小規模試験 |

## 未確定事項

- 議決の定足数と専門領域の必須条件は会議タイプごとに決める。AI多数決は人間の決定権と区別する。
- KGIは成果物ごとに人間との企画段階で決める。数値化できない成果には観察可能な受け入れ条件を置く。
- 外部接続のサービス、アカウント、操作許可範囲、監査周期は接続時に設定する。現時点で接続済みとは扱わない。

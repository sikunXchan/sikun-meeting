# 実行モード・専門ツール・参考資料

2026-09-29。0.8.7 の実装に対応する。

## 企画の採用と無人運用

「自動で進める」と「無人運用」は別の設定である。

| 進め方 | 無人運用 | 企画の採用 | 採用後の失敗・再起動 |
| --- | --- | --- | --- |
| 自動（UIの既定） | オフ | コンサルタントの回答を自動採用 | 手動で再開 |
| 自動 | オン | コンサルタントの回答を自動採用 | 対象の失敗を再試行し、再起動後も再開 |
| 確認 | オフ | 人間の確定を待つ | 手動で再開 |
| 確認 | オン | 人間の確定を待つ | 採用後に再試行・自動再開 |

自動進行では、依頼後の人間確認を挟まず、AIの作業・内部確認・納品まで進める。無人運用を併用すると、許可された範囲で再試行・継続も行う。コード実行部門にはファイル編集、コマンド実行、ネットワーク接続が可能な工程がある。企画確認モードでも、採用後の全操作を個別に人間が承認する仕組みではない。アプリのメール機能は送信前の画面確認を維持するが、SDKのコマンド経由の外部操作を一律に防ぐという意味ではない。

予算・期限・回数上限・無進捗による停止は再試行しない。会議の正式な決定は従来どおり人間が確定し、自動の討論要約とは区別する。

## 専門ツール

| 担当 | 工程 | 提供する操作 | 限界 |
| --- | --- | --- | --- |
| Researcher・Legal・Healthcare・PublicPolicy・Privacy・Sustainability | 作業・レビュー | Claude: WebSearch / WebFetch。Codex: live Web検索とページ閲覧 | シェルのネットワーク権限は追加しない。取得失敗・認証が必要な資料は未確認と記録。Claudeでは読み取りツールを名前だけで事前許可せず、作業フォルダと参考資料フォルダ以外の読み取りを `dontAsk` で拒否する（任意のファイルを読んでURLで送る経路を防ぐ） |
| QA・Frontend・Accessibility・Mobile | 作業・レビュー | ローカルHTMLを分離したChrome/Edgeで開く。入力、クリック、キー操作、画面幅変更、アクセシビリティツリー、状態確認、再読込 | Chrome/Edgeが必要。外部URL・開発サーバー・任意JavaScript実行は提供しない。音声読み上げ・モバイル実機・OSネイティブUIは未検証 |
| 全員 | 作業・レビュー・達成判定・KGI確認 | Claude: `calculate`（厳密な計算。名前付きの段階計算、%・べき乗・丸め）と `read_table`（csv/tsv/xlsxの読み取りと数値列の合計） | 書き込み・コマンド・外部通信なし。作業フォルダと参考資料フォルダの外、シンボリックリンクで外へ出るファイルは読まない。Codex実行には未提供 |
| 全員 | 会議・相談・計画・納品 | 既存の閲覧またはテキスト処理 | Web・ブラウザ・計算の検証ツールは提供しない |

内部確認では、担当AIのツール使用記録（コマンド・URL・計算の名前。結果は含まない）を確認役に渡す。報告で実行済みとされた検証が記録にない場合は未実施として扱う。記録の認証情報らしい値は伏せる。

分離ブラウザはメイン側で起動し、実行ごとに使い捨ての認証トークンを渡す。作業中は新しく作ったHTMLも開ける。レビューでは、CSSやJavaScriptだけの修正でも既存HTMLを確認できる。失敗や中断でもブラウザを閉じ、操作記録を活動へ残す。

Codexの検索設定は、[公式のweb_search設定](https://learn.chatgpt.com/docs/config-file/config-basic#web-search-mode)と同梱SDKの `ThreadOptions.webSearchMode` に従う。ネットワークや個別コマンドの制約はSDK・OSの実行環境にも依存し、役割の説明文だけによる禁止を強制制御とは呼ばない。

## 参考資料の受け渡し

1. ファイル選択ダイアログをメインで開き、選択されたファイルの内容をその時点で読み取る。
2. 画面へ返すのはIDと表示名だけ。ファイルパスを受け取る作成APIは廃止する。
3. IDは選択したウィンドウに紐づける。作成成功時に消費し、失敗時は再使用可能にする。同時の二重使用、別ウィンドウ、再読み込み・終了後のIDは拒否する。
4. 内容を `userData/data/commission-references/<案件ID>/` へ保存し、AIに絶対パスを渡す。作業リポジトリ内へはコピーしない。資料の内容は実行指示と区別する。

上限は10件、1件20 MB、合計100 MB。ディレクトリ、保存領域のシンボリックリンク、作業フォルダまたはGitリポジトリ内への保存を拒否する。選択後に元ファイルが変更されても、保持した内容を使う。旧版が作業フォルダ内に保存した資料は自動削除しないため、既存案件のコミット対象は利用者が確認する。

この変更は「侵害された画面から任意パスをコピーさせる」経路を閉じる。AIプロセス自体の全ファイルアクセスを新たに封じる変更ではない。

## スキルの定義と更新

全39体に対応する38スキルを `src/core/skills/catalog/<ID>/SKILL.md` に統一した（EngineerとBackendはimplementationを共有）。`specialties.ts` は役割名・担当選定用の情報だけを持ち、手順と確認基準を持たない。

各SKILL.mdのfrontmatterに `name`、`description`、`metadata.version` を置く。トップレベルで許可するのは標準の6項目（name / description / license / compatibility / metadata / allowed-tools）だけで、YAMLとして解析し、未知の項目・重複キー・不正な型を拒否する。`metadata.version` はアプリでの記録用に必須とし、文字列の `major.minor.patch` で管理する。外部形式の根拠は [Agent Skills仕様](https://agentskills.io/specification) と [Claudeの互換性説明](https://code.claude.com/docs/en/skills#using-skill-frontmatter-outside-claude-code) を参照。

本文の構成は「成果物・手順・確認基準」、用語は「受け入れ条件」に揃える。descriptionには作業の対象と利用場面を記す。共通の段階・権限・資料の扱い・証拠のルールは `catalog.ts` の `COMMON_SKILL_RULES` から、適用スキルの先頭に一度だけ渡す。これらはアプリの実行方針であり、SKILL.mdを外部へ単独で持ち出した場合には含まれない。外部で利用するツールや権限は、利用先の環境で別途設定する。

変更したスキルだけ版を更新する。0.8.8では全38本の本文を整理したため、従来1.0.0だった18本を1.1.0、従来1.1.0だった20本を1.2.0とした。UI・実行プロンプト・Run履歴は同じ定義を使い、過去のRunの版を書き換えない。

本文から相対リンクした `references/` と `scripts/` の同梱テキストを読み込める。ビルドではスキルディレクトリ全体をコピーし、実行時には資料の内容をプロンプトへ展開するため、配布版のASAR内パスをAIが直接開く必要はない。参照先はスキルディレクトリ内の許可したテキスト形式に限り、1ファイル16 KiB・8ファイルまで。スクリプトは自動実行せず、利用時にも担当の既存権限を守る。QAの確認表、Legalの論点表、Financeの感度分析表を同梱した。

## 版ごとの実績

設定 → AI → 専門家のスキル → 各担当 → 版ごとの実績で確認する。開くと最新の保存記録を集計し、開いたままのときは「更新」で再取得できる。集計用の別データベースは作らない。

0.8.8以降は各内部確認の判定に `workRunId` と `reviewRunId` を保存する。集計は、同じ依頼・仕事に属する完了済み作業とレビューが明示的に対応し、判定が一意に決まるものだけを使う。過去の判定は日時や最終状態から推測して補完しない。

- 作業側：差し戻し率 = 内部確認で差し戻された作業実行数 ÷ 内部確認済みの作業実行数。
- 確認側：差し戻し判定率 = 差し戻しと判断したレビュー実行数 ÷ 判定を記録したレビュー実行数。確認スキル自身の合格率ではない。
- スキルID・版・担当・工程・実行元・観測されたモデルで分ける。要求したモデルを実際に使ったモデルと見なさず、複数モデルを使用した場合も別条件にする。
- 再試行は別の実行として数える。実行中・失敗・中断は分母に含めない。完了していて判定との対応がない実行は「未集計」。分母が0のときは「—」で、0%とは区別する。
- 目標検証での未達や利用者の追加依頼は、この内部確認の率には含めない。旧記録・不正な参照・重複判定の除外件数も表示する。

案件の難しさ、確認者、その時点の共通ルールなどは同一条件とは限らない。この集計は傾向を調べるためのもので、率の変化だけでスキル修正の効果は断定しない。効果を検証するときは、同じ評価課題と判定基準で版を比較する。

計画には全39体のIDと短い役割名を渡す。成果物の詳細・手順・確認基準は担当の工程で渡し、確認基準を二重に挿入しない。

## 確認方法

`npm test` で、全スキルのLF/CRLF同値、文字数、版、同梱資料、計画の全分野保持、両SDKのツール設定、ブラウザのロール接続、資料選択IPCと保存境界を検証する。ブラウザが利用できる環境ではChrome/Edgeを実際に起動し、キーボード・画面幅・アクセシビリティツリー・外部接続遮断を確認する。

新しいWebツールのテストはSDKへ渡す設定とプロンプトの検証であり、LLMによる有料の検索実行は含めない。LF/CRLFの検査はWindows上で両形式を直接パーサーへ渡すもので、Linux/macOS上でテスト全体を実行したという意味ではない。

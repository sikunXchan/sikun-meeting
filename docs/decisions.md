# 判断理由の記録

## D-001：人間は企画を確定し、以後の仕事はAIが進める

- 日付・状態：2026-09-24・採用
- 根拠：ユーザーはITコンサルタントAIと企画し、その後はSIerへ委託するようにAI専門家へ実装と納品を任せたいと明示した。
- 選択：企画確定を通常の人間の確認点とし、その後の計画・担当・実作業・内部確認・納品は自動進行する。人間は進行を見て修正を依頼できる。
- 制約：外部で不可逆な操作を含む案件の扱いは企画内容と個別環境に依存する。

## D-002：全員に同じ実作業能力を与え、採用状態で所管を表す

- 日付・状態：2026-09-24・採用
- 根拠：ユーザーは既存21人を維持し、全員がPCを操作できる一方で、担当外の方針を独断採用しない運営を希望した。
- 選択：SDKの標準ツールを役職で制限しない。仕事には担当・所管・確認者を記録し、所管外の仕事は所管AIが確認するまで提案状態にする。
- 制約：共通のOS権限があるため、ファイル変更そのものを事前に強制遮断する仕組みではない。自動追跡は作業ディレクトリ内に限る。

## D-003：モデルの通常・重要・代替を分ける

- 日付・状態：2026-09-24・採用
- 根拠：ユーザーは通常Sonnet、重要時Opus 5.5、代替Haikuを希望した。
- 選択：既定をSonnet 5、計画と重要仕事・所管判断をOpus 5.5、混雑・利用不可時のSDK代替をHaiku 4.5にする。要求モデルと応答モデルを別々に保存する。
- 実装上の理由：同梱SDK 0.3.258のClaude CodeはOpus 5.5に未対応だったため、SDK 0.3.281へ更新し実呼び出しで確認した。

## D-004：SDK推定料金を画面と停止条件から外す

- 日付・状態：2026-09-24・採用
- 根拠：ユーザーはSDKをサブスクリプション利用として扱い、推定料金の表示を不要とした。
- 選択：設定と実行履歴から金額を除き、SDKの金額予算指定と推定料金による自動停止を撤廃する。呼び出し回数、1回のターン数、時間制限は維持する。
- 互換性：旧案件に保存された金額上限は適用しない。SDKが返す推定値は内部診断用の記録に残す。

## D-005：委託案件ごとにCodexを選べるようにする

- 日付・状態：2026-09-24・採用
- 根拠：ユーザーはCodexにも対応させ、その後Codexで実際のリポジトリを改良することを希望した。
- 選択：既存案件はClaudeのまま維持し、新規案件でClaude/Codexを選ぶ。CodexはChatGPTログイン済みCLIをSDK経由で使い、既定モデルを`gpt-6-sol`とする。
- 納品の扱い：実SDK試験でCodexの納品文生成が止まったため、その工程を60秒で打ち切る。作業と内部確認が済んでいる場合に限り、保存済みの記録から失敗理由付きの代替納品書を作る。中断や作業失敗は納品扱いにしない。

## D-006：Projectに継続するAIコミュニティを設ける

- 日付・状態：2026-09-24・初期版を採用
- 根拠：ユーザーはAIのコミュニティを大きく実用的なものとして育てたいと希望し、最初の実装を指示した。
- 選択：Projectごとに課題・発言・委託案件・採用知識をつなぐ。AIは既存活動から課題を提案でき、選択された専門AIが順に議論する。実作業は委託案件を再利用する。
- 運用境界：AI呼び出しは利用者の操作を起点とする。人間の採用内容だけを次の議論の確定知識として扱う。委託案件の内部作業は従来どおり人間の逐次承認なしで進める。定時自動投稿と公開コミュニティは後続の判断とする。

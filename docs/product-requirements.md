# Sikun Meeting の製品要求

状態：現行実装を反映（2026-09-29）
根拠：ユーザーの委託型AI組織への要求、[作業要件](../.steering/20260924-autonomous-ai-organization/requirements.md)

## 利用者が達成したいこと

利用者が目標を入力する。自動進行ではITコンサルタントAIの企画案を自動採用し、確認モードでは人間が相談・編集して確定する。その後はAI専門家が仕事を計画し、成果物を作り、内部確認を経て納品する。人間は進行を確認し、必要な修正・調整を伝える。Projectでは人間とAIが継続して課題を投稿・議論し、成果と採用知識を次の仕事に引き継ぐ。38分野とITコンサルタントによる会議、意思決定、Action Itemは維持する。

## 現行版の境界

コミュニティのAI発言と課題提案は画面操作で始める。定時の自動投稿は含めない。作業はアプリ起動中に進む（ウィンドウを閉じてもトレイに常駐する）。無人運用でない案件は再起動後に中断状態で止まり、確認してから手動で再開する。自動進行と無人運用は独立した設定であり、両方を有効にすると人間の企画確認なしで動く。確認モードを選んだ場合だけ企画確定を待つ。アプリのメール送信機能は人間の確認を必要とするが、コード実行部門のコマンドやネットワーク操作すべてを人間の承認で保護するものではない。KGIの達成判定は監査と同じく `現在値 >= 目標値` であり、小さいほど良い指標は達成率などに言い換えて登録する。Codexの非コード部門はコマンドからネットワークへ接続できない（ResearcherとLegalの組み込みWeb検索は別）ものの、コマンド実行自体は止められない（Codex SDKに個別ツールの許可設定がないため）。成果ファイルの自動追跡は選択した作業ディレクトリ内で行う。SDKのBashからPC操作CLIを使える環境はあるが、GUIを要する全種類の仕事を配布版で検証したわけではない。HTML成果物のQA等は、元ファイルを編集しないアプリ提供の隔離ブラウザで操作を検証できる。音声読み上げの実行は提供しない。Chrome実機とCodex実Runで入力・クリック・結果確認を検証済み。Action Itemからの委託は画面操作で始まり、作成と同時の自動取り込みではない。人格間の文化形成と、委託案件の実行トレースのアニメーションは今後の機能である（後者は2026-09-25に保留）。

## 受け入れの根拠

`npm test` で相談→企画確定→作業→内部確認→納品・修正、役割境界、停止・再開、呼び出し回数上限を検証する。Windows配布版の試験では、Sonnet 5の相談、Opus 5.5の計画、Sonnet 5の作業・内部確認・納品を完走し、試験用 `greeting.txt` の作成と採用を確認した。既存会議表示、22人の一覧、委託画面、金額を出さない実行履歴も確認した。詳細は[作業タスク](../.steering/20260924-autonomous-ai-organization/tasklist.md)。推奨値への画面整理と追加スキルの検証は[新しい作業タスク](../.steering/20260926-defaults-and-live-trial/tasklist.md)に記録する。隔離ブラウザQAはChrome実機の自動テストと、Codex SDKの読み取り専用QAによる入力・クリック・表示結果の確認で検証した。[試験記録](../.steering/20260926-browser-qa-trial/tasklist.md)に詳細を残す。

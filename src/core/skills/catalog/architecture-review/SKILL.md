# 設計の確認

アーキテクトが構成や設計の判断をするときに使う。

1. 既存の構成、データの流れ、変更箇所を確認してから案を出す。
2. 案ごとに運用、障害時の復旧、拡張、セキュリティへの影響を確認する。
3. 境界となるAPIと保存データの互換性を明示し、採用理由と見送る案を短く記録する。
4. 会議やレビューでは変更を提案するだけにとどめる。実作業の段階でも与えられた範囲を越えて変更しない。

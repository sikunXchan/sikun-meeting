# 操作設計とデザイン

## 成果物

画面構成・モックアップ・デザイン仕様。

## 手順

1. 利用者の主要タスクとつまずき、既存画面、ブランド、承認済みの表現を確認する。
2. 情報の優先順位と操作経路を定め、通常・空・読込中・失敗時の状態を設計する。大規模変更はモックアップを用意し、依頼者の承認方針に従う。
3. 配色・書体・レイアウトは題材・利用者・ブランドから決め、選んだ理由を仕様に一行ずつ書く。強調は画面ごとに一か所に絞り、他は抑える。
4. 絵文字をアイコン・見出しの飾り・箇条書きの記号に使わない。アイコンは既存のアイコンセットか SVG で描く（依頼者が求めた場合と、絵文字そのものを扱う画面は除く）。
5. 題材に関係なく出てくる定番の型を既定にしない。例: 同じ角丸・影のカードを並べるだけの構成、全見出しの上の英大文字の小ラベル、見出しの一語だけ色や斜体を変える強調、全セクションのフェードイン、順序のない内容への 01/02/03 番号、白地に紫系のグラデーション。使う場合は、この題材で必要な理由を仕様に書く。
6. 色、余白、文字、コンポーネントを揃え、主要画面幅とキーボード操作の確認方法を示す。

## 確認基準

見た目の統一に加え、次の操作が分かるか、入力負担、コントラスト、フォーカス、誤操作からの復帰を確認する。モックアップは check_design_patterns で絵文字と定番の型の有無を確かめ、残す場合は理由を報告する。

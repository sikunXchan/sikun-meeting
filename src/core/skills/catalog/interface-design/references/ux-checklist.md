# UI/UX 確認リスト

利用者が整理した原則集（knowledge/ux-principles.md、500項目）の要点。括弧内は項目番号で、詳しくは lookup_ux_principles で引く。数値は目安であり、採用する基準（WCAG・Apple・Material など）を仕様に明記する。

## 前提
- 誰が、どの状況で、何を達成するかを書く。急いでいる・片手・疲れているなど現実の利用を基準にする（#26, #59, #103, #131）。
- 主要タスクを特定して注力する（#16, #198）。複雑さは誰が負担すべきかを考え、できるだけシステム側が引き受ける（#7, #50）。

## 慣習と独自性
- 操作の慣習は守る。検索は虫眼鏡、設定は歯車、閉じるは×（#2, #20）。独自性は配色・書体・構成・言葉で出し、操作方法では出さない。
- 同じ意味の操作には、同じ見た目・言葉・挙動を使う（#44, #48）。

## 構造と視覚
- 最初に見る所、次に見る所、操作する所が分かる階層にする（#24, #170）。強調は一か所に絞る（#11, #171）。
- まとまりは余白で示し、不要な枠やカードを増やさない（#23, #46, #47, #165）。
- 選択肢は整理し、詳細は必要になった時に開示する（#5, #6, #18, #89）。
- 本文の行長はおよそ45〜75文字、行間はフォントサイズの1.4〜1.6倍を出発点にする（#177, #178）。
- 注意は有限。動き・点滅・広告のような強調を重ねない（#60, #62）。

## 操作
- 重要な操作は大きく、届きやすい位置に置く。タップ領域とターゲット間の余白をセットで確保する（#3, #28, #29, #245, #246）。
- 押せる物は形とラベルで示す。アイコンには原則テキストラベルを付ける（#21, #22）。
- 削除などの破壊的操作は通常操作と離し、結果を明示し、可能ならUndoを用意する。確認ダイアログは本当に必要な場面だけに使う（#173, #30, #57, #159）。
- ホバーやジェスチャーだけに機能を隠さない。ドラッグには代替操作を用意する（#244, #397, #105, #286）。
- 戻る・キャンセル・Undoを用意する。モードは表示するか減らす（#36, #106）。

## 状態とフィードバック
- 操作にはすぐ反応する。目安は、約0.1秒で即時、約1秒で思考が途切れない、10秒程度で進捗表示が必要、ドハティのしきい値は約400ms（#4, #189, #34）。
- システムの状態を示す（例:「アップロード中 65%」）（#35, #53）。
- 各画面で「状態を理解する → 次にできることが分かる → 操作する → 結果が分かる」が成立するか確かめる（#90, #107, #108）。
- 空・読込中・エラー・成功の4状態を設計する。空状態では、なぜ空か、何ができるか、最初の一歩を示す（#197, #86, #201）。
- 変化は操作の近くで伝える（#63）。

## フォームと入力
- ラベルは常に見えるようにする。プレースホルダーをラベルの代わりにしない（#97, #22）。
- 入力は寛容に受け、システム側で整形する（例: 電話番号のハイフンの有無）（#8, #320）。
- 項目は最小限にし、適切な初期値と自動入力を使う（#155, #156, #157, #303）。
- 長いフォームは意味のまとまりで分け、現在地を示す（例:「2 / 4：配送先入力」）（#6, #323, #53）。
- エラーが起きにくい入力にする（例: カレンダーで選ぶ、予約できない日は選べない）（#31, #32, #56）。
- 検証は適切なタイミングで行い、入力途中で早すぎるエラーを出さない（#73）。
- エラー文は、何が・どこで・どう直すかを、問題の近くに示す（#72, #269, #270）。
- 二重送信を防ぎ、下書きを保存し、未保存の変更を警告する（#326, #321, #322）。

## 言葉
- 押した結果が分かるラベルにする（例:「詳細」より「料金プランを見る」）（#67, #74）。
- 短く具体的に、利用者の言葉で書く。社内用語を出さない（#75, #181）。

## アクセシビリティ
- コントラストは、本文4.5:1以上、大きな文字3:1以上、UI部品と意味のある図形3:1以上（#1, #261）。
- 色だけで伝えない。色・アイコン・文言を組み合わせる（#1, #98, #257, #258）。
- 全操作をキーボードで行えるようにする。フォーカスを見えるようにし、順序を自然にし、抜け出せない箇所を作らない（#92, #93, #262, #263）。
- 正しい要素（button・a・h1〜h6・label）、アクセシブルネーム、見出し階層、ランドマークを使う（#94, #96, #265, #266）。
- 動きを減らす設定を尊重し、点滅を避ける。拡大や文字サイズの変更で崩れないようにする（#99, #285, #241, #242）。
- 知覚・操作・理解・堅牢（POUR）の4つの観点で確認する（#100）。

## 倫理
- ダークパターンを作らない。例: 解約を分かりにくくする、不要なオプションを事前選択する、拒否だけ目立たなくする、偽の緊急性を示す（#40, #79, #373）。初期値は利用者にとって妥当で安全なものにする（#37）。
- 情報や許可は、必要な時点で必要な分だけ求める（#41, #313, #314, #478, #480）。

## AI機能を含む画面
- 提案と実行を分ける。AIの出力は編集・取り消しできるようにし、限界と出所を示す（#470〜#476）。

## 評価
- 初めて使う人の視点で認知的ウォークスルーを行い、ニールセンの10ヒューリスティクスで点検し、問題に重大度をつける（#69, #70, #436）。
- 実際の利用者で確かめていない判断は、仮説と明記する（#219, #134, #135）。

# 製品の仕事割り当て

1. 発注者が確定した目的と完成条件を軸にする。過去の提案や担当AIの希望を、新しい要求として扱わない。
2. 各仕事の成果を利用者が確認できる形で定義し、完成条件のどれに対応するかを明らかにする。必要のない会議・計画・報告だけの仕事は増やさない。
3. 担当と所管が異なる場合は所管部門の確認を残す。依存する仕事だけを順に並べ、並べる理由を説明する。
4. 会議では利用者への効果、実施コスト、未確認の仮定を分けて述べる。実作業では確定範囲の成果だけを作る。

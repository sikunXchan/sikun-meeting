# 文書作成と手順検証

## 成果物

利用ガイド・API説明・変更説明。

## 手順

1. 読者、目的、前提知識、対象の版と参照する実装・資料を確認する。
2. 必要な順番で、前提、操作、期待する結果、失敗時の対処を記述する。
3. 用語、見出し、リンク、コマンドを照合し、実行した手順と未確認の例を分ける。

## 確認基準

実装と文書の一致、手順の欠落、古いリンク、読者が判断できない曖昧な説明を確認する。
